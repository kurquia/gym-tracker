1 · The big picture

Four layers, imports only point down

Every file belongs to one of four layers. A file may import from its own layer or a lower one, never a higher one, so you can understand the bottom (the database) without knowing anything about the screens. The numbers on the diagram are counted from the code on every run.

Solid arrow = imports arriving at that layer. Dashed = one feature borrowing from another, with the count. Filled = the biggest part. Click a box to jump to its files.

Two files in a cycle import each other, directly or through others. One cycle in lib/data/ is expected: the DAOs need AppDatabase, and lib/data/database.dart re-exports them so a screen only has to import that one file.

Now: 8 files (exercises_dao.dart, history_dao.dart, routines_dao.dart, settings_dao.dart, workouts_dao.dart, database.dart, progress.dart, workout_logic.dart).

4 · Data flow

What happens when you tap something

Screens never keep their own copy of the data. They watch a provider, usually a live stream from the database, and they call a DAO method when you do something. The write makes the stream emit again, and every screen watching it redraws. It works like a spreadsheet: change one cell and everything depending on it recalculates by itself.

// A ConsumerWidget is a widget that can use providers.
final data = ref.watch(someProvider).value;                  // read + subscribe (step 3)
...
onPressed: () => ref.read(databaseProvider).someDao.act(id); // act (step 1)

The same pattern runs on every screen. Tests swap databaseProvider for an in-memory database (test/test_db.dart), so the real screens run against throwaway data.

A small glossary

Widget
Everything on screen: a button, a row, a whole page. A widget is a description that Flutter redraws whenever its data changes. Like a function data → picture.
Stateful / State
A widget that keeps small local memory, such as the text in a box you're typing into. setState changes it and redraws.
BuildContext
A widget's place in the tree of widgets. The context you see everywhere; it's how a widget reaches the theme or the navigator above it.
Consumer…
ConsumerWidget and ConsumerState are widgets that can use ref to reach providers.
Provider
Riverpod's shared value or stream, like a cell in a spreadsheet that others depend on. ref.watch = read and redraw on change; ref.read = read once, e.g. inside a button press.
.family / .autoDispose
family = a provider with a parameter (one exercise's history, by id). autoDispose = thrown away when nobody watches it any more.
Notifier
A provider with methods that change its value. Used for state kept in memory, not in the database.
drift
The SQLite library. Tables are Dart classes; queries are Dart method chains instead of SQL strings.
DAO
Data access object: a class holding the queries of one area (workouts, routines, history…). Screens go through these instead of touching the tables.
Schema / migration
The schema is the structure of the database, numbered by version. A migration is the step that upgrades an existing file from one version to the next without losing data.
build_runner
The code generator. Reads the drift classes and writes the .g.dart files next to them (row classes, query plumbing). Never edit those by hand.
part
part 'x.g.dart'; makes another file count as part of this one. That's how generated code joins the file it was generated from.
go_router
Gives each screen an address like /exercises/42, so navigation is “go to this address”.
Sheet / dialog
A panel sliding up from the bottom / a box in the middle of the screen. Both open above the page and return a result when closed.
Future / Stream
A value that arrives later (like an asyncio awaitable) / a sequence of values over time (like an async generator).
async*, yield
A function that produces a Stream, written like a Python generator.
int?, !, ??
int? may be null, like Optional[int]. x! asserts it isn't. x ?? y means y when x is null.
final / const
final = assigned once. const = known at compile time, so Flutter can reuse the object instead of rebuilding it.
extension
Methods added to an existing class from outside it, without subclassing.
Isolate
A separate thread with its own memory, like a process in multiprocessing: it talks by messages. The notification's Pause button runs in one.
Hot reload
Puts changed code into the running app and keeps its state, so you see a change without restarting.
